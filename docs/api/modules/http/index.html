HTTP

Overview​

The HTTP module provides a comprehensive HTTP client functionality for JavaScript code running in the Goja runtime. It supports making HTTP requests with configurable options including headers, query parameters, request body, timeouts, retry logic, and rate limiting.

Module Import​

const http = require('dfp/http');

API Reference​

Core Methods​

http.request(method, url[, options])​

Makes an HTTP request with the specified method.

Parameters:

  • method (string): HTTP method (GET, POST, PUT, DELETE, etc.)
  • url (string): Request URL
  • options (object, optional): Configuration options

Returns: Response

http.get(url[, options])​

Convenience method for GET requests.

http.post(url[, options])​

Convenience method for POST requests.

http.put(url[, options])​

Convenience method for PUT requests.

Options Object​

OptionTypeDescription
headersobjectHTTP headers to send with the request
paramsobjectURL query parameters
bodystringRaw request body
jsonanyJSON payload (automatically stringified and sets Content-Type header)
timeoutstring/numberRequest timeout (e.g., "5s", "1m", or milliseconds)
retryCountnumberNumber of retry attempts (default: 1)
ratenumberRate limit (requests per second)
verifybooleanEnable/disable response verification (default: true)
statusCodeOkbooleanWhen true, requires status code 200 or 201 to consider request successful

Response Object​

PropertyTypeDescription
textstringRaw response body
headerobjectResponse headers
statusCodenumberHTTP status code

Methods:

  • json(): Parses response body as JSON and returns the parsed object

Examples​

Basic GET Request​

const http = require('dfp/http');

// Simple GET request
const response = http.get('https://api.example.com/users');
console.log(response.statusCode);
console.log(response.text);

GET with Query Parameters​

const http = require('dfp/http');

const response = http.get('https://api.example.com/search', {
    params: {
        q: 'javascript',
        page: '1',
        limit: '10'
    }
});

POST with JSON Body​

const http = require('dfp/http');

const response = http.post('https://api.example.com/users', {
    headers: {
        'Authorization': 'Bearer token123',
        'X-Custom-Header': 'custom-value'
    },
    json: {
        name: 'John Doe',
        email: 'john@example.com',
        age: 30
    }
});

// Parse JSON response
const data = response.json();
console.log(data.id);

POST with Raw Body​

const http = require('dfp/http');

const response = http.post('https://api.example.com/data', {
    headers: {
        'Content-Type': 'text/plain'
    },
    body: 'raw text data'
});

Advanced Configuration​

const http = require('dfp/http');

const response = http.get('https://api.example.com/data', {
    timeout: '10s',
    retryCount: 3,
    rate: 5, // 5 requests per second
    verify: true,
    statusCodeOk: true, // Require 200 or 201 status code
    headers: {
        'User-Agent': 'MyApp/1.0'
    },
    params: {
        format: 'json'
    }
});

if (response.statusCode === 200) {
    const data = response.json();
    // Process data
}

Error Handling​

const http = require('dfp/http');

try {
    const response = http.get('https://api.example.com/users/999', {
        verify: true,
        statusCodeOk: true
    });
    
    const user = response.json();
    console.log(user);
} catch (error) {
    console.error('Request failed:', error.message);
    // Handle error (includes truncated response body for debugging)
}

Behavior Details​

Retry Logic​

  • Retries occur for network errors or server errors (status >= 500)
  • Special handling for 429 (Too Many Requests) with exponential backoff
  • Stops retrying on client errors (400-499) unless statusCodeOk is enabled

Logging​

  • Debug level logs for requests and successful responses
  • Info level logs for client and server errors
  • Response body truncated to 500 characters in error messages
  • Request body truncated to 1000 characters in debug logs

Rate Limiting​

  • Rate limiters are shared globally by hostname
  • When rate is specified but rateLimitName is not provided, uses the request hostname
  • Each limiter enforces the specified requests per second

Timeout Handling​

  • Supports string format (e.g., "5s", "100ms", "1m")
  • Falls back to numeric milliseconds
  • Creates a new context with timeout for each request

Notes​

  • The HTTP client is shared globally with default settings
  • Response bodies are automatically closed
  • JSON parsing uses jsoniter for performance
  • All methods are synchronous in the JavaScript context
